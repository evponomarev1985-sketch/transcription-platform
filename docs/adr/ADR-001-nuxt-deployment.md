# ADR-001: Размещение Frontend как Nuxt SPA/static

- Статус: Accepted
- Дата: 2026-09-22

## Контекст

Нужен внутренний кабинет транскрибации. SEO не требуется. Бэкенды и gateway запускаются в Docker. В будущем возможна миграция в Kubernetes.

## Решение

Выбран вариант **Nuxt SPA/static** с сборкой фронтенда в статические ассеты и раздачей через Nginx (api-gateway).

## Почему

1. Эксплуатационно проще: нет отдельного runtime SSR-процесса Node.js в проде.
2. Меньше операционных рисков на VM: меньше контейнеров и потребления ресурсов.
3. Для внутреннего кабинета SSR не дает значимой бизнес-выгоды.
4. Прямая совместимость с будущим Kubernetes: статический frontend легко переносится как отдельный контейнер/ingress route.
5. Кэширование статики и versioned assets проще на edge/gateway.

## Последствия

- Плюсы:
  - проще деплой и rollback;
  - быстрее cold-start;
  - меньше поверхность отказа.
- Минусы:
  - нет SSR для первого рендера;
  - runtime конфиг ограничен env-инъекцией на этапе сборки/entrypoint.

## Альтернативы

Nuxt SSR в Docker-контейнере отклонен как избыточный для данного типа приложения.
